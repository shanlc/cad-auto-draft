# 建筑底图识图复核（块 / 参照怎么处理）

结论先说：**底图识别必须先分清楚三类东西，再谈准确率——
普通图元、块、外部参照。** 混在一起用“看图 AI”猜，坐标一定会漂；
按图元 + 块展开 + 参照补齐的确定性解析，才是能进施工图流程的做法。

## 1. 输入：先转 DXF，DWG 不能直接读

- 本程序只读 DXF。DWG 是私有二进制格式，ezdxf 读不了。
- 转换方法（任选其一）：
  1. AutoCAD / 天正打开底图，用 `DXFOUT` 另存为 DXF
  2. 免费的 ODA File Converter：DWG → DXF 批量转换
  3. 天正出图时直接另存 DXF 底图
- 转 DXF 时注意：不要只转当前视口，要转模型空间；单位保持
  原图单位（院图多为毫米），程序默认按毫米换算成米。

## 2. 三类图元的处理

### 普通图元：直线、多段线、圆、文字

- 直线 / 多段线：直接取坐标，闭合多段线才可能是房间轮廓。
- 文字 / 多行文字：只认 DXF 里的文字对象，不做图片 OCR。
  扫描图、PDF 图片底图要先矢量化，否则文字和墙线都不在图里。
- 图层名是重要线索，但各院命名不统一，所以本程序以几何
  + 块名为主，图层为辅，不硬编码某个院的图层名。

### 块（BLOCK / INSERT）：必须递归展开

建筑底图里洁具、门、柱、楼梯、管井几乎都是块，而且经常嵌套：
洁具块里套着圆和线，户型块里套着洁具块。

本程序的做法（`plan_parser.py`）：

- 读到 INSERT，先记块名和插入点、比例、旋转角
- 再递归展开块定义里的图元，变换叠加到模型坐标
- 嵌套上限 10 层，循环引用直接截断并记入警告，不死循环
- 块名关键词识别洁具，见 `FIXTURE_KEYWORDS`：
  马桶 / 坐便 / 蹲便、洗脸盆 / 面盆、淋浴 / 花洒、
  洗菜盆 / 水槽、洗衣机、地漏，以及英文 toilet / basin / shower / sink 等
- 块名 / 图层含管井 / 楼梯 / 电梯 / 柱时，按展开后的包围盒记为障碍物
- **你院里的块名如果不在关键词里，洁具会漏认。** 这是 v0.1
  最常见的漏认原因，解决办法是在 `FIXTURE_KEYWORDS` 里加你们的
  块名，或者先跑 `--plan-out` 看 `block_counts`，再补映射。

### 外部参照（XREF）：不能静默丢掉

很多建筑底图是参照进来的：给排水图里只挂了一个建筑底图的参照，
宿主文件里本身没有墙线。

- 判断方法：INSERT 的块在宿主文件里没有任何几何图形，
  就按参照处理。
- 处理方法：
  - `--xref 参照块名=参照文件.dxf` 显式指定，或
  - 把参照 DXF 放在宿主文件旁边、同名，程序会自动找
- 找不到参照文件时，程序会在输出里明确列出
  `missing_xrefs`，并继续跑其余部分，**不会假装底图是完整的**。
  正式使用前必须把缺失参照补齐，否则房间、洁具都会少。

## 3. 房间怎么定

- 闭合多段线，宽、深都 ≥ 1 m，面积 ≥ 2 m2，才算房间候选
- 房间名 = 落在该矩形内的第一个文字
- 同一轮廓画两遍的，会按坐标去重
- 不是闭合多段线的房间（比如墙是分开的直线）目前不算房间，
  只影响房间名和洁具归属，不影响管线布线——管线以洁具点位为准。

## 4. 识别后的人工复核清单

跑完先看 `--plan-out` 的 JSON，不要直接进布线：

- [ ] 房间数、洁具数和原图对得上吗
- [ ] `missing_xrefs` 是空的吗
- [ ] `warnings` 里有没有“未识别到房间 / 洁具”
- [ ] `block_counts` 里出现频率最高的未知块是什么，要不要加关键词
- [ ] 坐标原点、单位（毫米 / 米）对吗，建筑尺寸和原图一致吗
- [ ] 立管、管井位置是不是解析出来的障碍物，还是要手填

复核通过后，再把解析结果作为 `--plan` 输入跑粗稿，
或用 `--input` 覆盖层数、危险级、立管位置等设计参数。

## 5. 本版不做的事

- 不做图像 OCR、不认扫描 PDF、不认位图
- 不重建墙厚、门洞、门扇开启方向
- 不认天正的建筑自定义对象（墙、门窗对象在 DXF 里可能
  是代理图形或块，须先在天正里炸开 / 转成普通图元再转 DXF）
- 不保证所有院的命名都能零配置识别，关键词映射是必做的
  一步院内适配工作
